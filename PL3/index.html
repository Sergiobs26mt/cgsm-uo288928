Memoria

Descripcion de la practica

En esta sesion se trabajo con texturas avanzadas en three.js. Se implementaron mapas topologicos (bump maps) para dar sensacion de volumen a las superficies, texturas de video mediante un canvas intermedio, controles interactivos de la escena con lil-gui y una escena de primera persona con desplazamiento de camara mediante FirstPersonControls.

Tareas realizadas y resultados

Se desarrollaron cuatro escenas (prac3-1 a prac3-4). En la primera se compararon dos cubos ladrillo, uno con textura basica y otro con mapa topologico. En la segunda se aplico un video como textura a un plano usando un canvas intermedio actualizado en cada frame. En la tercera se añadio un control interactivo lil-gui para modificar el parametro bumpScale en tiempo real. En la cuarta se construyo una escena 3D explorable con una rejilla de suelo, cubos con materiales multiples y controles de camara en primera persona.

Ejercicio 1 (prac3-1): Texturas avanzadas — mapa topologico

Se modifico la escena base para mostrar dos cubos lado a lado: el izquierdo con textura de ladrillo simple (MeshPhongMaterial con map) y el derecho con textura mas mapa topologico (bumpMap, bumpScale: 10). Ambos giran continuamente sobre el eje Y mediante requestAnimationFrame. El uso de MeshPhongMaterial en lugar de MeshBasicMaterial fue necesario para que el bump map reaccionase a la iluminacion y el efecto de relieve fuese visible.

Ejercicio 2 (prac3-2): Textura de video

Se creo un plano que utiliza como textura el trailer de Sintel. Para respetar la restriccion de los navegadores modernos sobre reproduccion automatica de audio/video, se añadio una capa overlay que exige una interaccion del usuario (boton "Iniciar") antes de construir la escena y llamar a video.play(). El frame actual del video se copia en cada iteracion del ciclo de renderizado al canvas intermedio mediante drawImage(video, 0, 0, w, h) y se marca la textura como needsUpdate = true. El plano rota sobre el eje Y. Se añadio un control Pause con lil-gui para detener la rotacion.

Dificultad: inicialmente el video no se veia completo: se mostraba recortado con una banda negra superior. La causa era que drawImage(video, 0, 0) dibuja el frame en su resolucion nativa (854x480), pero el canvas es de 480x204, por lo que el contenido se recortaba. La solucion fue añadir los parametros de ancho y alto al llamar a drawImage: drawImage(video, 0, 0, image.width, image.height).

Ejercicio 2 Opcional (prac3-2-opt): Video reproducido al revés

Como ejercicio opcional se implemento la reproduccion inversa del mismo video. La API HTML5 no soporta playbackRate negativo en los navegadores actuales, por lo que se uso una tecnica de cadena de seeks: al completarse cada seek (seeked event), se dibuja el frame en el canvas y se lanza inmediatamente el siguiente seek con currentTime -= 1/30. De esta forma los frames se encadenan a la velocidad maxima que el navegador puede resolver cada seek. El bucle requestAnimationFrame solo se usa para la rotacion del plano y el render, sin interferir con el timing del video. Al llegar a currentTime = 0 se salta al final para hacer loop.

Ejercicio 3 (prac3-3): Control interactivo de bumpScale

Partiendo de prac3-1, se añadio un panel de control lil-gui con un slider para modificar el parametro bumpScale del material (rango -4 a 4, paso 0.1). El valor del control se aplica al material en cada frame dentro de la funcion de animacion: material.bumpScale = controlData.bumpScale. Se verifico que sin esta linea el slider no tenia efecto visible en la escena.

Ejercicio 4 (prac3-4): Escena de primera persona

Se creo una escena con una rejilla (GridHelper 800x40) a modo de suelo, dos cubos de 50 unidades con materiales multiples (una cara especial enfrentada y el resto con ladrillo), luz direccional y luz hemisferica para iluminacion natural. Se importo FirstPersonControls de three.js y se configuro con velocidades de movimiento y vision. En el ciclo de renderizado se obtiene el delta de tiempo con THREE.Clock y se llama a controls.update(delta). El usuario puede desplazarse con W/S/A/D y mover la vista con el raton.

Respuestas a cuestiones del guion

¿Por que es necesario usar MeshPhongMaterial con el bump map? Porque el bump map usa la iluminacion para simular relieve. Con MeshBasicMaterial no hay calculo de luz y el efecto no se aprecia. Solo los materiales que calculan iluminacion (Phong, Lambert, Standard) pueden mostrar el efecto del bump map.

¿Que efecto tiene bumpScale sobre la textura? Es un factor de escala que amplifica o reduce el desplazamiento percibido de la superficie segun el mapa topologico. Valores altos exageran el relieve; valores negativos invierten el efecto (valles donde habia picos). Con valor 0 el bump map no tiene efecto.

¿Por que se necesita un canvas intermedio para la textura de video? Three.js no puede usar directamente el elemento video como textura en tiempo real de forma eficiente. El canvas actua de intermediario: en cada frame se copia el frame del video al canvas y se señala la textura como needsUpdate = true para que el renderer la suba a GPU.

¿Por que es necesario el boton de interaccion en la escena de video? Los navegadores modernos bloquean la reproduccion automatica de medios con audio para evitar experiencias intrusivas al usuario. Exigen que la reproduccion se inicie como respuesta directa a un gesto del usuario (click, teclado, etc.).

Dificultades encontradas y solucion

1) Recarga automatica de la pagina: el servidor de desarrollo de Webpack tenia activo el Live Reload, lo que provocaba recargas de pagina al detectar cambios en ficheros. Se resolvio añadiendo liveReload: false y hot: false al bloque devServer de webpack.config.js.

2) Video recortado en la textura: drawImage(video, 0, 0) dibujaba el frame en su resolucion nativa, superior al canvas de 480x204, recortando el contenido. Se corrigio pasando las dimensiones del canvas como parametros de destino a drawImage.

3) Control GUI sin efecto en la escena: el slider de bumpScale modificaba el valor del objeto controlData pero no el material. Fue necesario añadir material.bumpScale = controlData.bumpScale dentro del bucle de animacion para que el cambio se propagase al renderizador en cada frame.
